## 项目简介

申论帮是一个面向公务员考试申论科目的 AI 智能备考平台。平台集成了多种大语言模型，通过多模型 Ensemble 评分机制，为考生提供客观、精准的申论批改服务。同时提供卷库训练、能力诊断、好词好句积累、备考计划等功能，覆盖申论学习的全流程。

### 为什么选择申论帮？

| 特点 | 说明 |
|------|------|
| **多模型评分** | 支持 6+ 种大模型同时批改，Ensemble 综合评分，有效消除单一模型的偏差 |
| **分题型评分** | 针对归纳概括、综合分析、提出对策、贯彻执行、大作文五种题型，使用不同的评分维度和提示词 |
| **采分点覆盖法** | 逐条对照参考答案的采分点，判断 full/partial/none，而不是笼统打分 |
| **手写识别** | 支持拍照上传手写答案，OCR 自动识别（百度/腾讯/Tesseract） |
| **批改问答** | 针对批改结果与 AI 对话，追问扣分原因和改进方法 |
| **零配置部署** | Docker 一键部署，SQLite 数据库无需额外配置 |

## 核心功能

### 1. AI 智能批改

平台的核 心功能，支持五种申论题型的自动评分：

| 题型 | 评分维度 | 评分方式 |
|------|----------|----------|
| 归纳概括 | 踩点命中(70%)、语言简洁(15%)、归纳准确(10%)、条理清晰(5%) | 采分点逐条覆盖判定 |
| 综合分析 | 逻辑链(30%)、覆盖(30%)、深度(20%)、语言(10%)、格式(10%) | 逻辑链完整性 + 要点覆盖 |
| 提出对策 | 问题定位(20%)、针对性(25%)、可行性(25%)、具体性(20%)、格式(10%) | 万能对策检测 + 可行性评估 |
| 贯彻执行 | 格式(20%)、目的(25%)、内容(30%)、语言(15%)、字数(10%) | 9 种文种格式检查 |
| 大作文 | 立意(25%)、论证(25%)、结构(20%)、语言(20%)、创新(10%) | **智能体批改**：审题自检 + 两阶段评分 + 评审团仲裁（分档赋分制四档） |

**多模型协作模式：**

- **Ensemble 模式**：多个模型同时批改，综合评分，消除单一模型偏差
- **Fallback 模式**：按优先级依次尝试，任一模型成功即返回结果
- **单模型模式**：指定单个模型快速批改

**支持的 AI 模型：**

| 模型 | 提供商 | 特点 |
|------|--------|------|
| DeepSeek V4 Pro | DeepSeek | 主力批改模型，综合能力强 |
| DeepSeek V4 Flash | DeepSeek | 快速批改，成本低 |
| LongCat-2.0 | LongCat | 推理模型，深度分析 |
| GPT-5.6-Sol | OpenAI 兼容 | 高精度批改 |
| Claude Opus 4.8 | Anthropic 兼容 | 语言表达评估 |
| 豆包 Seed 2.1 Pro | 火山引擎 | 国产模型，中文优化 |

**批改方式切换（常规批改 / Agent 批改）：**

考生在作答页用一个滑动切换器选择批改方式（常规=蓝色滑块、Agent=浅紫色滑块，选择持久化）；结果页的「重新批改」弹窗同样支持切换。

| 方式 | 说明 |
|------|------|
| 常规批改 | 沿用多模型批改流程，大作文走两阶段（审题→评分），快速省成本；边界分数/体裁存疑时仍会自动升级复核 |
| Agent 批改 | 在大作文上启用完整的「AI 评卷组」：审题自检 + 两阶段评分 + 5 维度评审团并行评审 + 仲裁官综合定档，更准但耗时更长 |

### 2. 批改问答

批改完成后，用户可以针对批改结果与 AI 进行多轮对话，深入理解自己的问题所在。

**使用流程：**

1. 在左侧「批改记录」列表中选择一条已批改的作答
2. AI 自动加载该次批改的完整上下文（题目、用户答案、得分、采分点命中/遗漏、AI 评语）
3. 用户可自由提问，或点击快捷问题一键提问
4. AI 基于批改记录给出针对性回答，支持 Markdown 排版（表格、列表、加粗、代码块）

**快捷问题：**

| 问题 | 学习目标 |
|------|----------|
| 我为什么得这个分数？主要问题出在哪里？ | 理解扣分原因 |
| 哪些采分点遗漏了？应该怎么补上？ | 对照采分点查漏补缺 |
| 参考答案为什么要这样写？答题思路是什么？ | 学习标准答案的答题逻辑 |
| 如何改进我的答案？请给我一个修改示例 | 获得具体改进指导 |
| 这类题型的答题框架和步骤是什么？ | 掌握题型通用方法论 |

**技术特点：**

- **服务端对话存储**：聊天记录保存在服务器 `chat_messages` 表，按用户 + 批改记录隔离，换设备登录也能看到历史对话
- **流式输出**：AI 回复采用 SSE（Server-Sent Events）实时流式输出，逐字显示，体验流畅
- **上下文注入**：每次对话自动注入批改记录完整上下文（题目、答案、得分、采分点、AI 评语），总计约 6000 字符
- **Markdown 渲染**：AI 回复支持完整 Markdown 渲染（标题、表格、列表、加粗、代码块、引用块）
- **多模型支持**：批改问答使用的模型可在管理后台「功能模型配置」中独立指定，不影响批改模型

### 3. 真题卷库

平台内置 1000+ 套申论真题，覆盖：

- **国考**：2011-2026 年中央机关及其直属机构考试
- **省考**：31 个省/自治区/直辖市历年真题
- **联考**：多省联考真题
- **事业单位**：综合应用能力测试

每套试卷包含完整的题目、给定材料、参考答案和采分点。支持按年份、省份、考试类型筛选。

**题目反查所属试卷**：只记得题目、记不清是哪份试卷？卷库页提供「按题目内容定位所属试卷」——输入题干关键词（如「最是需要自己的地方」），立即列出命中的题目及其所属试卷（标题/年份/地区/分值），一键跳转作答；主搜索框同样支持按题目内容搜索试卷。

### 4. 题型训练

针对五种申论题型的专项练习：

- 按题型分类刷题，强化薄弱环节
- 记录每次练习的得分和维度表现
- 追踪各题型的进步趋势

### 5. 能力诊断

基于批改数据的多维度能力分析：

- **统一能力画像**：把各题型实际维度（大作文立意/论证、对策针对性/可行性等）归一化为五个能力维度——**内容覆盖 / 逻辑分析 / 语言表达 / 格式规范 / 立意论证**（0-100 百分比），跨题型可比、始终有值（未练到的维度显示 --，不再出现 0 分）
- **五题型得分 + 趋势**：各题型均分对比与近 10 次得分走势
- **优势/短板识别**：画像 ≥70 为优势、<50 为短板；推荐项带**练题深链**（跳转题型训练并自动选题型），配合「重新诊断」按钮形成「诊断 → 练题 → 再诊断」闭环
- **每次批改小结**：批改结果页顶部展示本次得分、较上次同题型进退、本次最强/最弱维度与下一步建议

### 6. 素材学习

- **好词好句**：人民日报、求是网、新华网精选素材，按主题分类
- **时政热点**：最新时政热点整理，关联申论考点
- **AI 造段**：根据主题自动生成申论规范表达

### 7. OCR 手写识别

支持拍照上传手写答案，自动识别为文字：

- **百度 OCR**：手写模型，识别率最高（免费 500次/天）
- **腾讯云 OCR**：通用高精度（免费 1000次/月）
- **Tesseract**：本地离线识别，无需联网

图像预处理流水线：灰度化 → 对比度增强 → 自适应二值化 → 去噪 → 锐化

**多页识别拼接**：申论答案常跨两页以上，支持分页依次拍照——识别结果自动**追加**到答案末尾（而非覆盖），多页内容拼接成完整答案后再提交批改，第一页不会被第二页覆盖。

### 8. 个人中心

个人中心聚合学习数据与账号管理：

| 模块 | 功能 |
|------|------|
| 学习概览 | 本周批改数、平均分、得分趋势、能力雷达、题型分布 |
| 批改记录 | 分页浏览全部批改历史（上一页/下一页，累计数取真实总数） |
| 套餐详情 | 各套餐余额、剩余天数/次数、每日限额（标注"凌晨0时刷新"） |
| 账号设置 | 修改昵称/邮箱/手机/个人简介 + 修改登录密码 |

**套餐体系**：管理员后台自定义套餐（按次 / 按天 / 每日限额），兑换码开通；同套餐叠加（按天延长到期日、按次累加次数）；用户专属标识徽章；扣费按模型消耗计费，优先级 月卡 → 次卡 → 余额。

### 9. 客服工单

用户提交建议/问题反馈（工单），推送到管理员后台处理并回复，用户随时查看回复、追问或关闭：

- **提交工单**：选择分类（建议 / 问题反馈 / 投诉 / 其他）+ 标题 + 详细内容
- **管理员回复**：管理后台「工单管理」查看全部工单（状态/分类/关键词筛选 + 分页），对话流中直接回复，回复后状态变为「已回复」
- **用户查看回复**：顶部导航「工单」入口带**未读新回复红色徽标**（打开详情即标记已读），个人中心也有「我的工单」入口
- **持续对话**：用户可追回复（状态回到待处理），任一方可关闭工单
- **状态流转**：待处理 open → 已回复 replied → 已关闭 closed；管理员可重开

### 大作文智能体批改框架（AI 评卷组）

大作文是主观议论文，没有标准采分点，最容易出现"立意判断被考生答案带偏"的问题。因此平台对大作文启用 **「AI 评卷组」智能体协作框架**：审题自检 → 两阶段评分 → 评审团 → 仲裁，把"这道题该写什么、写得怎么样、该定几档"拆成多个有明确分工的智能体角色协作完成。

#### 为什么需要两阶段？

传统的单轮批改把"材料和题目 + 考生作文"一起丢给模型，模型会**边读作文边猜材料该写什么**，两个判断互相污染：
- 立意判断容易受作文内容干扰（模型读到一篇跑题的作文，可能被"带跑"而误判材料核心）
- 缺少客观的"标准答案锚点"，同一道题不同模型评分标准不一致

两阶段框架把「这题该写什么」抽成独立步骤，产出**与考生无关的《审题锚点》**，再拿它去量作文。

#### 框架总览

```
用户提交大作文
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ 阶段一：独立审题（不看考生作文）                       │
│                                                     │
│   输入：题目 + 给定材料                              │
│   调用：审题模型（LLM）                              │

│    │                                                │
│    ├── 核心议题：材料真正讨论的核心矛盾（一句话）      │
│    ├── 命题倾向：材料支持什么/反对什么/期待论证什么     │
│    ├── 切题立意：2-3 个可接受的中心论点方向（按切题度排序）│
│    ├── 跑偏陷阱：容易写偏的方向                       │
│    ├── 核心概念：必须正确理解的政策术语/关键提法        │
│    ├── 文体要求：议论文 / 策论文，分析为主还是对策为主   │

└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ 阶段二：对照锚点评分（锚点 + 考生作文）                │
│                                                     │
│   输入：审题锚点 + 考生作文                           │
│   调用：评分模型（LLM）                              │
│   按序执行 5 步判定：                                │
│   ① 文体判定：议论文 / 策论文 / 纯对策罗列            │

│   ② 立意对照：提炼考生中心论点，与锚点切题立意比对       │
│      （准确 / 基本准确 / 有偏差 / 严重偏离）            │
│   ③ 逐段分析：按自然段逐段点评优点/问题/修改建议        │
│   ④ 结构与内容：标题点题 / 开头亮论点 / 分论点平行 /     │
│      论据支撑 / 结尾升华                              │
│   ⑤ 综合定档：先由文体+立意定档，再在档内按结构/内容/   │
│      语言微调（一类 31-40 / 二类 21-30 / 三类 11-20 /  │
│      四类 0-10）                                     │
│                                                     │
│   产出：档次 + 分数 + 立意对照 + 逐段分析 +            │
│         整体评价 + 提分路径（Top 3 改进点）            │
└─────────────────────────────────────────────────────┘
```

#### 锚点缓存：按模型隔离

- 审题锚点**只与题目相关，与考生无关**，因此同一道题只需生成一次
- 但不同模型的命题理解能力不同，弱模型生成的浅层锚点会拖累强模型，因此**锚点按模型隔离**：
  - 缓存键 = `SHA256(题目内容 + model_id)`，复合主键 `(anchor_key, model_id)`
  - **A 模型生成的锚点只给 A 用**，B 模型独立生成自己的锚点
- 首次答题冷启动（2 次调用：审题 + 评分），同题同模型后续命中缓存（1 次调用）
- 真题锚点可由教研人员审核后固化（`is_reviewed` 字段预留），越用越准

#### 审题官自检（P1）

审题锚点生成后，由「申论审题复核官」**再复核一轮**：逐项核对作答要求覆盖、核心概念抓取、立意切题、材料把握、陷阱提醒、文体判断，发现遗漏或跑偏则直接修订锚点。自检只跑一轮控制成本与时延，失败时保留原锚点不影响批改；自检元信息随锚点一起缓存（`_meta` 字段），同一道题只自检一次。

#### 评审团 + 仲裁（P2）

在常规两阶段评分的基础上，对 **边界分数（±5 分落任一档线）/ 体裁存疑 / 用户选择 Agent 批改** 的作文，升级为评审团模式：

- **5 位独立维度评审官并行评审**：立意 / 论证 / 结构 / 语言 / 创新，各出一份独立评分、档次投票与针对性意见（互相看不到对方，避免从众）
- **仲裁官综合定档**：尊重多数票、处理跨档分歧、压体裁错误，输出最终档次、最终分、一致度与分歧说明，并给出「初评 → 仲裁」差异（让考生看到评审团是否调整了定档）
- **成本与时延控制**：5 位评审并行（总时延 ≈ 单个评审 + 仲裁），子评审输出 token 上限压缩；任一位评审失败即丢弃，不足 2 位成功则整体降级回常规结果，绝不阻断批改

#### 结果页展示（AI 评卷组流水线）

大作文批改结果以「AI 评卷组」流水线的形式呈现，全题型统一框架：

| 区域 | 内容 |
|------|------|
| 综合判定卡 | 档次（一类~四类彩色渐变）+ 大分数 + 评审结论 + 模式/一致率/评分差/有效·失败模型 chips |
| 智能体流程 stepper | ①审题官 → ②评分官 → ③评审团 → ④仲裁官，每步状态徽章（已完成/已缓存/已触发·维度数/已定档），可点击跳转，显示"N 个智能体协作完成本次批改" |
| ① 审题官卡 | 审题锚点（核心议题/可选立意/易写偏/核心概念/可用论据）+ 自检徽章（已缓存/本次生成·已自检修订） |
| ② 评分官卡 | 文体判定 / 立意对照 / 结构检查（左列）+ 逐段分析 / 整体评价（右列） |
| ③ 评审团卡 | 触发原因 + 5 维度独立评分卡（评分/档次投票/亮点/问题/建议） |
| ④ 仲裁官卡 | 最终定档 / 一致度 + 初评→仲裁差异 + 分歧说明 + Top 3 提分路径 |
| 判定卡差异条 | 常规结果显示「⚖ 智能体复核：初评 X ＝/→ 仲裁 Y」；未走评审团时提供「✨ 升级 Agent 批改」一键重批 |

普通题型（归纳/分析/对策/贯彻）共用同一套页面框架，隐藏智能体卡，展示维度分析、参考要点对照、命中/遗漏等。

|------|------|

## 快速部署

### 前置要求

- Docker 20.10+
- Docker Compose 2.0+

### 1. 克隆项目

```bash
git clone https://github.com/1523826455647/Essay-Grading.git
cd Essay-Grading
```

### 2. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，填写以下必填项：

```env
# 管理员账号（首次启动自动创建）
ADMIN_USERNAME=admin
ADMIN_PASSWORD=你的强密码（至少16位）

# LLM API 配置（至少配置一个）
LLM_API_KEY=sk-your-api-key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat

# 安全密钥（部署脚本自动生成，勿使用默认值）
SECRET_KEY=随机字符串
JWT_SECRET=随机字符串
LLM_CREDENTIALS_KEY=加密密钥
```

### 3. 启动服务

```bash
docker-compose up -d
```

访问 `http://localhost:18004` 即可使用。

### 4. 可选：配置 OCR

```env
# 百度 OCR（推荐，手写识别准确率高）
BAIDU_OCR_API_KEY=你的API_KEY
BAIDU_OCR_SECRET_KEY=你的SECRET_KEY

# 腾讯云 OCR
TENCENT_OCR_SECRET_ID=你的SECRET_ID
TENCENT_OCR_SECRET_KEY=你的SECRET_KEY
```

### 5. 本地开发

```bash
pip install -r requirements.txt
python -m src.app
```

## Android 客户端（APK）

申论帮同时提供 Android 客户端：一个轻量的 WebView 封装，把 Web 应用打包成可直接在手机上安装的 APK。

### 安装包获取

GitHub 发布页的 **Assets** 中带 `shenlun-apk-*.apk` 即是安装包。安装后在手机桌面上显示为「申论帮」App，无需浏览器即可使用全部功能。

### 手动构建（可选）

APK 由 GitHub Actions 自动构建，无需本地环境。如需手动构建，需要 JDK 17 + Android SDK：

```bash
cd android
gradle wrapper --gradle-version 8.5
./gradlew :app:assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

> 修改 `android/app/build.gradle` 顶部的 `TARGET_URL`，即可把 APK 指向新的服务端地址。

### 客户端功能

- 返回键返回上一页，支持网页后退
- 支持文件/照片选择上传
- 视频播放支持全屏横屏
- 外链自动用系统浏览器打开
- 断网时显示离线提示，联网后自动恢复
- 记住上次访问页面，重启回到上次位置
